# Website building

- Manage pages.
- Manage components.
- Manage layers — where things live and exist.
- Framing: either a new lens/perspective, or keep everything on the same frame.
- A button can link to a database or an external site (via a line).

## Software levels

Shallow to deep. Complexity here = wiring, not algorithm.

- **Static content** — no logic; fixed pages. Ex: brochure site, portfolio.
- **Interactive front-end** — client-side behavior; no stored data. Ex: calculator, quiz, Figma prototype.
- **CRUD / data-backed app** — UI + data store + actions + external APIs; shallow logic. Ex: booking page, catalog, chatbot / AI-wrapper, internal tool. **← baio target.**
- **Product-scale system** — many services, real scale, custom algorithms / ML. Ex: Instagram feed ranking, Uber dispatch, SaaS platform.
- **Systems / infrastructure** — low-level, performance- and correctness-critical. Ex: QNX (real-time OS), Linux kernel, Postgres, compilers, firmware.

Terms: static + interactive + CRUD = **application software**; product-scale adds **distributed systems / ML**; the bottom tier is **system software**.
